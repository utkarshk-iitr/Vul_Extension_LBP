The main benchmark metric they use is %Perfect Predictions (%PP), also called Perfect Prediction. It is defined as the percentage of vulnerable functions for which the model generates a repair that exactly matches the ground-truth human-written repair; equivalently, it is the number of correct predictions divided by the number of test functions. They use this same metric for the main comparison against VRepair and CodeBERT, for the pre-training ablation, for the tokenization study, and for the component ablation.

Here is the exhaustive list of quantitative metrics / measurement axes actually used in the paper:

%Perfect Predictions (%PP) — the core evaluation score for VulRepair and all baselines/ablations.
Top-k %Perfect Predictions under different beam sizes — they report %PP at beam sizes 1, 2, 3, 4, 5, 10, and 50. This is still the same metric, just measured at different candidate ranks.
Per-CWE %Perfect Predictions — %PP broken down by CWE type, including the Top-10 most dangerous CWEs and other CWE groups. The table also reports the proportion of instances in each CWE group.
Function length (#tokens in vulnerable function) — used to stratify accuracy into bins such as 0–100, 101–200, …, 500+.
Repair length (#repair tokens) — used to stratify accuracy into bins such as 0–10, 11–20, …, 50+.
Cyclomatic Complexity (CC) — used to analyze how function complexity affects repair accuracy, with bins like CC 0–10, 11–20, 21–30, 31–40, and >40.
OOV / new-token statistics — they measure whether a repair contains tokens not present in the vulnerable function, the percentage of test pairs with OOV issues, and the average number of new tokens for correct vs. incorrect repairs.
Dataset descriptive statistics — not benchmark scores, but reported measurements include #Tokens in Vulnerable Function, #Repaired Tokens, and CC of Vulnerable Function with quartiles/median/average in Table 1.
Derived improvement margins over baselines — e.g. “13% better,” “21% better,” “30%–38% improvement,” and “9%–14% improvement.” These are derived from %PP, not separate evaluation metrics.

One more important point: the paper explicitly says that broader APR measures such as semantically correct repairs and plausible patches were not evaluated, because the dataset did not include test cases.

So, in plain terms: the paper’s actual benchmark score is %Perfect Predictions, and everything else is either a slice of that score or a dataset/analysis variable used to explain it.
